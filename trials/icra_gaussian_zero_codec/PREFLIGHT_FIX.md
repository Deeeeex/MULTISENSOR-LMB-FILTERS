# 编码预检之前的单位夹具与记录修正

第一轮纯编码单位测试退出 0，验证了原始字节透传、空向量、正负零和
非零向量的全部 64 位。补充实际 Bernoulli 包后，结构整体比较误用了
`isequal`，因为模板中存在相同位置的 NaN 占位轨迹字段而失败。
独立诊断的整体结果为 `PLAIN_EQUAL=0 NAN_EQUAL=1`，实际编码器中的
位模式往返断言通过。修正为 `isequaln`，不改变编码、融合或模型。

调度出现一次顺序错误：在确认第二轮单位测试退出码前启动了源冻结
和预检。预检的第一步再次执行相同单位测试并退出 1，尚未开始任何
跟踪帧，也没有生成任何结果文件。原单位夹具、生成器、运行器、冻结
脚本和当时的源清单均保存在 initial_preflight，失败日志完整保留。
只有修正后的单位测试退出 0 后，才重新固定源并启动预检。

同时在静态检查中发现，标签诊断行把 double 标签与 uint16 编码标记
直接拼接，会让 MATLAB 把整行变为 uint16，导致大于 65535 的标签
饱和。现将标记明确转换为 double 后记录；编码字节仍保持 uint16。
该修正发生在任何新编码跟踪输出之前，不涉及融合公式或模型参数。

最初诊断打印逐字段结果时，结构数组的逗号列表使各对象之间不同的
字段也被列出；整体 `isequaln(received,old)` 结果才是跨编码器的
结构比较。后续正式夹具直接对完整结构和所有系数位模式断言。
